# 企业内控合规测评平台

面向法务、审计部门的合规学习与测评系统：发布**反舞弊 / 数据安全 / 采购红线**测验，员工在线学习、考试并**电子签署学习确认**；高风险岗位执行更高通过分数线。系统对"谁、在什么时候、学过哪一版测验、考了多少分、是否签署"进行**逐人、逐场、逐事件的不可篡改留痕**，并支持公开验真与定期证据链校验——不是只展示通过人数。

## 快速开始

```bash
npm start        # 依赖已随环境提供：express + better-sqlite3（无其他运行时依赖）
# 打开 http://localhost:3000
```

首次启动需初始化（仓库已附带 `data/compliance.db`，删除后可重新初始化）：

```bash
rm -f data/compliance.db*
node server/seed.js
```

## 如何满足"证明谁在什么时候学过，而不是只展示通过人数"

### 1. 逐人逐场的证据模型（`attempts` + `attempt_events`）
每一次考试都是一条独立记录，**包括未通过、进行中、重考**（历史不覆盖），并通过三条追加式事件还原全过程：

- `started`：开考事件——固化**开考时刻**、员工身份快照（姓名/部门/岗位/是否高风险）、试题版本与试题快照、该员工适用的通过线、IP、User-Agent、设备指纹；
- `submitted`：交卷评分事件——固化**交卷时刻**、服务器评分结果、逐题作答与对错、作答用时；低于最小学时自动标记 `too_fast`；
- `signed`：电子签署事件——固化**签署时刻**、本人逐字输入姓名形成的电子签名与学习确认声明文本。

员工首页、合规看板均按**人 × 测验**呈现状态（未开始 / 进行中 / 已交卷待签 / 已签署）、考试次数、历史最高分，而不是聚合成一个通过人数。

### 2. 双哈希链防篡改（`hash.js` / `evidence.js` / `routes/verify.js`）
- **证据事件链**与**审计日志链**各自为追加式哈希链：`record_hash = SHA256(prev_hash + 规范化事件内容)`，链头贯穿全部记录；
- 直接改库改分：哈希链虽仍闭合，但"状态表 vs 证据事件载荷一致性校验"会立刻报出 `分数不一致：状态表=99，证据事件=100`；
- 删除/插入/重排任意事件：下一记录的 `prev_hash` 立即失配，`/api/verify/chains` 报出断裂点（已通过删除事件的对比测试验证）；
- 审计部门可在"证据链校验"页一键校验，并可定期比对链头哈希（外部可信时间点留存）。

### 3. 试题版本快照（`quiz_versions`）
题目每次发布固化为不可变版本（v1、v2…）；员工开考时把当版题目完整复制进考试记录（`questions_snapshot`）。事后修改题目、发布新版**不影响已产生的学习证据**，证据详情明确标注"学的是哪一版"。

### 4. 高风险岗位双线规则（`quizzes` + `users.high_risk`）
测验同时设置普通线（默认 80）与高风险线（默认 90），开考时按员工岗位快照确定本场分数线并固化；未达本人适用线**服务端拒绝签署**，只能重考。看板对"高风险岗位未完成"单独计数预警。

### 5. 凭证导出与公开验真
- 每条已签署记录可导出 **CSV 凭证**（直接可交稽核/检查）或 **JSON 证据包**（含全部事件、哈希、逐题作答）；
- 凭证上的"验真码"= 签署事件哈希。任何人无需登录，在"公开验真"页或 `GET /api/verify/code/:hash` 即可核验：学习者、部门岗位（含高风险标识）、测验名称与版本、事件时间、成绩与分数线、签署时间、电子签名。

### 6. 审计日志
登录成功/失败、出题、改版发布、指派、开考、交卷、签署、人员与高风险标记变更……全部写入第二条哈希链（`audit_logs`），可按动作/对象/人/时间检索。

## 技术结构

```
server/
  index.js            Express 入口（静态托管 + API）
  db.js               SQLite 表结构（WAL，外键开启）
  auth.js             scrypt 密码哈希 / Bearer 会话 / 角色中间件
  hash.js             稳定序列化 + SHA256 链式哈希
  evidence.js         追加事件、审计写入、链校验
  seed.js             初始账号与三套测验
  routes/
    auth.js  quizzes.js（含版本发布/指派）  attempts.js（开考/交卷/签署）
    dashboard.js（逐人状态）  evidence.js（证据包/CSV导出/清单）
    audit.js  admin.js（用户岗位）  verify.js（链校验/公开验真）
public/               零构建原生 SPA（登录/考试/签署/看板/证据库/验真/管理）
data/compliance.db    SQLite 证据数据库
```

安全要点：评分与计时全部在服务端完成（前端不可信）；题目正确答案不下发到考试接口；签署姓名服务端强校验；所有写操作留痕；无任何外部服务依赖。

## 建议的运维/稽核动作

1. 审计每月在"证据链校验"页执行校验，并截图/留存链头哈希；
2. 重要检查前导出相关人员 CSV 凭证，凭验真码在公开验真页复核；
3. 高风险岗位名单由管理员在"用户与岗位"维护，变更动作进入审计日志；
4. 数据库文件按企业留存制度备份（WAL 文件需一并备份或先 checkpoint）。
